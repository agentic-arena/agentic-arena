first skill: anti-slop

Interfaces that don't look generated.

A coding agent that works from real product facts, real tokens, and real components. Then proves the result with measurements.

read the design see the repository

MIT licensed. Twelve tests across three Python versions. This page makes zero network requests.

the problem

The same interface, over and over.

Ask a coding agent for a landing page and you can guess what arrives: a gradient hero, three equal feature cards, a headline about unlocking potential. The cause is not laziness. An agent with no product facts fills the gap with the average of everything it has read.

The fix is not a better adjective in the prompt. It is giving the agent real material to work with, then checking the result against something measurable.

how it works

Three layers, in order.

  • Ground

    Before markup: who the page is for, what the visitor has to do, and which facts are off limits. The agent writes the product record and the design record. On replica work it pulls the real palette, type scale and spacing out of the reference page instead of guessing them.

    PRODUCT.mdDESIGN.md

  • Rules

    A written playbook the agent cannot hand wave: one accent color, one radius system, one theme per page, a hero that fits the first screen, motion that sticks to transform and opacity, and a ban list of the patterns that make generated pages look related.

  • Audit

    The page is rendered in a real browser and measured: contrast on the rendered DOM, tap target sizes, horizontal overflow, page weight, and the delta against the reference. The verdict is pass, fail, or unverified, and unverified never turns green on its own.

the rubric

Written before the first page was built.

The audit is designed, not shipped. These are the numbers it will hold every generated page to.

  • body text contrast4.5:1 minimum
  • large text and borders3:1 minimum
  • tap targets on mobile44px minimum
  • accent colors per pageexactly one
  • font families per pagetwo, plus mono
  • external requestszero
  • page weightunder 300 KB

voice

The page reads the way the code is written.

Copy goes through the same linter as the docs. Three pairs from the swap list, shown as they were rejected.

  • leverage→use
  • seamless→say what works without friction
  • it's not just a tool, it's a platform→pick one and state it

This page passes the same linter. The three rejected phrases above are marked as quoted examples, which is the only exception the rules allow.
